Getting Started

Installation

  1. Download the latest .zip from the Releases page.
  2. Open Blender → Edit → Preferences → Add-ons.
  3. Click Install… and select the ZIP file.
  4. Enable Blender CTR Toolkit by ticking the checkbox.
Do not extract the ZIP – Blender installs it directly.
Addon enabled in Preferences

Compatibility

  • Blender 3.3 to 5.0 – Full support.
  • PS1 Resolution → requires Blender 3.5+.
  • Vertex Snap Modifier → requires Blender 4.0+.
  • Other features work on 3.3+.

Help Utilities

Buttons in the CTR panel header (right side):

  • Documentation – opens online docs
  • Tutorials – YouTube playlist
  • Report Issue – GitHub issue tracker
  • Keymaps – popup with shortcuts
  • Update – checks for new versions (turns red when ready)
Quick access to help resources.

Navigator Module

Navigate (Find Blocks)

Scans the active mesh in Edit Mode and detects all quadblocks and triblocks. It can start from:

  • Manual selection – If you select exactly the 4 faces of a block, its center vertex (quadblock) or its center face (triblock), the algorithm navigates from there.
  • Navigation points – If no selection exists, it uses constant materials marked as navigation points (defined in the Item List panel). Only materials assigned to exactly 4 faces forming a valid block are considered.

Performs a BFS search avoiding face conflicts, and automatically assigns groups (1..n) so that blocks in the same group do not share vertices – ideal for massive duplication.

Example: detecting quadblocks from a navigation point.

Reset (Clear Cache)

Deletes all addon data from the active object:

  • Constant materials (restores original materials; if missing, creates fallback copies by removing the _ID suffix).
  • Vertex groups whose names start with QB_ or TB_.
  • All cache properties (quadblock_centers, face_to_quadblock, quad_group_members, etc.).
This action cannot be undone. A confirmation dialog is shown before execution.
Warning dialog before clearing all data.

Quadblock

Selects only the center vertices of all detected quadblocks. Useful for inspecting or modifying the center of each block in bulk.

Triblock

Selects only the center faces (triangles) of all detected triblocks.

Invalid

Selects all faces that do not belong to any detected block (by comparing with the stored used_face_indices). Very useful to find leftover geometry, modeling errors, or faces that are not part of any quad/triblock.

Group Selection

Blocks are automatically grouped during Navigate (greedy coloring) so that two blocks in the same group never share a vertex. This allows duplicating whole groups without intersections.

Dropdowns show existing groups (e.g., Group 1: 12 quadblocks). Press Select to select the centers of all blocks belonging to that group.

Duplicate All Blocks by Group

Opens a file dialog to choose an export directory. Then:

  1. Duplicates all quadblocks and triblocks (respecting groups) inside the original mesh.
  2. Exports duplicates to an OBJ file (duplicates.obj) copying textures to a textures/ subfolder.
  3. Re‑imports the OBJ and separates loose parts into individual objects.
  4. Renames each object based on the constant material ID (e.g., Grass_ID05 → 05).
  5. Reassigns constant materials to their base material (strips the _ID suffix).
  6. Moves all resulting objects to a collection named Processed_Blocks.

During the process, PS1 Render and Vertex Snap modifiers are temporarily disabled to avoid conflicts.

Shortcut: Ctrl+L – Select block under cursor

In Edit Mode, hover the mouse over a face that belongs to a quadblock or triblock and press Ctrl+L. The 4 faces that form the whole block will be selected. Also works if you already have several faces selected (selects the corresponding blocks). Uses ray casting to detect the face under the cursor.

Navigation Points (constant materials)

To use Navigate without manual selection, you must mark some constant materials as navigation points in the Item List → Constant Materials panel. Each navigation point must:

  • Be a constant material (name contains _ID).
  • Have the Is Navigation Point checkbox enabled.
  • Be assigned to exactly 4 faces that form a valid quadblock or triblock.

Item List Module

The Item List panel gives you full control over quadblocks/triblocks, vertex groups, and constant materials. It is split into two display modes:

Vertex Groups Mode

Displays each block as a vertex group (QB_<id> or TB_<id>). Use this mode to manage groups, filter by issues, and quickly select geometry.

Generate

Creates a vertex group for every detected quadblock and triblock. Existing groups starting with QB_/TB_ are removed first to avoid contamination. Groups are named after the center element index (e.g., QB_42).

Vertex groups created for all blocks.

Clear

Removes vertex groups. By default only clears groups belonging to selected blocks (faces or centers). If you check Clear All in the confirmation dialog, all QB_* and TB_* groups are deleted.

Choose to clear all groups or only those of selected blocks.

Groups (Menu)

Opens a dropdown list of all existing block vertex groups. Selecting one will immediately select the corresponding block in the 3D view (faces and vertices). A quick way to focus on a specific block.

Pick any vertex group from the list to select the block.

Check

Adds the currently selected block(s) in the 3D view to the checklist (multi‑selection) of the Item List. The checkboxes in the list will be ticked accordingly. Use this to batch-process blocks later (e.g., clear, assign materials, export).

Selected block appears checked in the list.

Filters (QB/TB, Material, Issue)

Refine the list to show only specific blocks:

  • QB / TB toggles – show only quadblocks or only triblocks.
  • Material filter – show blocks that use a specific material (picked from a menu).
  • Issue filter – show only valid blocks, invalid geometry, out of range, invalid UVs, degenerated UVs, multiple materials, etc. (requires running Validate Groups first).
  • Search box – filter by name, ID, or block type.
Issue filter shows only blocks with invalid UVs.

Checkboxes & Multi‑selection

Each item in the list has a checkbox. You can tick multiple blocks. Then use the Select in 3D button (the check icon next to the search) to physically select all checked blocks in the viewport. The selection is updated in real time.

Tick several blocks, then click the check button to select them in 3D.

Pagination & Sorting

The list shows 10 items per page. Use the arrow buttons to scroll, or jump to first/last page. Sort by name (A‑Z / Z‑A) or by block type (QB first / TB first).

Navigate through many blocks easily.

Constant Materials Mode

Switch the display mode to Constant Materials using the top toggle. Here each block is represented by its constant material name (e.g., Dirt_ID05).

Assign

Assigns a unique constant material to the selected block. A dialog appears showing the base material (fixed) and lets you edit the ID suffix. The final name becomes BaseName_ID<value>. IDs must be unique across all constant materials on the object. The constant material is a duplicate of the base material, so you can later replace its texture without affecting others.

Set a custom ID for the block.

Clear

Clears constant materials. Options:

  • Clear from selected block (default) – restores the original base material.
  • Clear All – removes every constant material on the object.
  • Clear Invalid Only – removes only navigation points that are broken (do not form a valid 4‑face block).
  • Duplicate if missing – if the original base material is gone, the constant material is duplicated and stripped of _ID to become the new base.
Flexible clearing options.

Groups (Management Dialog)

Opens a dialog to organise constant materials into named groups. You can:

  • Create a new group (enter a name).
  • Delete an existing group.
  • Add checked materials to the selected group.
  • Remove checked materials from the group.

Once groups are defined, you can filter the list by group using the Groups button (the active group name appears on the button).

Create groups, add/remove materials, and filter by group.

Check (Constant Materials)

Same as in Vertex Groups mode: adds the currently selected block(s) in 3D to the checklist, but this time based on the constant material name. Checked materials appear ticked in the list.

Navigation Point Toggle

Each constant material can be marked as a navigation point. These serve as starting seeds for the Navigator module when no manual selection exists. The button in the list (star or dot icon) toggles this flag. You can also mass‑toggle navigation points for all visible items using the filter menu’s Toggle Navigation State button.

Mark a constant material as navigation point (star icon).

Filters (QB/TB, Material, Navigation, Search)

Constant Materials mode adds a Navigation Filter:

  • All – show all constants.
  • Navigation Points – show only materials marked as navigation points.
  • Constant Materials – show only non‑navigation constants.

Additionally you can filter by material name (the constant material itself) and use the search box. The same pagination and sorting as Vertex Groups mode apply.

Material Icons & Preview

Each item in the list shows the actual texture image of the material (if available) as an icon, making it easy to recognise blocks by their texture.

Issue Validation for Vertex Groups

Before using the issue filter in Vertex Groups mode, you must run Validate Groups (available in the Validator module when Scope = Vertex Groups, or directly via the Validate Groups button in the Item List panel). This analyses every vertex group and stores issues like invalid geometry, invalid UVs, out of range, etc. The issue filter then becomes active.

Run validation once to enable issue filtering.

Validator Module

Scope Selector

Determines what the Validator checks:

  • Objects – Analyses all mesh objects in the scene (or selected objects) for issues like invalid geometry, UV problems, out‑of‑range position, multiple materials, etc.
  • Vertex Groups – Analyses vertex groups named QB_* or TB_* on the active mesh object (requires generated vertex groups from Item List).
Switch between Objects and Vertex Groups scope.

ISSUES – Add suffix to objects

When Objects scope is active, this button (qb_tb.object_qb_tb_suffix) adds descriptive suffixes to object names based on the selected filter.

Examples of suffixes added:

  • _quadblock / _triblock – if the object is a valid block
  • _invalid_geo – invalid geometry
  • _invalid_uvs – UVs outside 0‑1 range
  • _degenerated_uvs – all UVs identical
  • _invalid_triblock_uvs – triblock with wrong UV arrangement
  • _out_of_range – vertices outside -500..500 box
  • _multi_mat – multiple materials on faces
  • _nonmesh – non‑mesh objects
  • _ngon – faces with more than 4 vertices
After clicking ISSUES, object names get informative suffixes.

ISSUES – Validate vertex groups

When Vertex Groups scope is active, this button (list.validate_vertex_groups) analyses every vertex group whose name starts with QB_ or TB_.

It detects the same issues as for objects (invalid geometry, UVs, out‑of‑range, multiple materials) and stores the results in the object property vertex_group_issues. These issues then become available in the filter dropdown and can be used by the Select and Remove buttons.

Running validation on vertex groups stores issues for later filtering.

SELECT – Select objects by filter

In Objects scope, this button (qb_tb.filter_select_objects) selects all objects in the scene that match the current filter (e.g., "Out of Range", "Invalid UVs", "Quadblocks").

It uses the same filter dropdown as the ISSUES button. The selection is added to the current selection (does not replace previous selection). The first matched object becomes the active object.

Select all objects with invalid UVs in one click.

SELECT – Select faces of vertex groups by filter

In Vertex Groups scope, this button (qb_tb.select_vertex_groups_by_type) does two things:

  1. Checks the matching vertex groups in the Item List checklist (switches display mode to Vertex Groups if needed).
  2. Enters Edit Mode and selects all faces belonging to those vertex groups.

If no validation data exists, it automatically runs Validate Groups first. The filter dropdown determines which groups are considered (e.g., "Invalid Geometry", "Out of Range").

Automatically select faces of all groups that are out of range.

CLEAR – Remove suffixes from object names

In Objects scope, this button (qb_tb.clean_object_suffixes) removes all validator‑added suffixes from every object in the scene, restoring original base names.

It strips suffixes like _quadblock, _invalid_uvs, _out_of_range, etc. Useful to clean up after validation.

One click to revert to original object names.

CLEAR – Clear vertex group issues

In Vertex Groups scope, this button (qb_tb.clear_vertex_group_issues) deletes the stored vertex_group_issues data from the active mesh object. It does not delete the vertex groups themselves, only the validation cache.

REMOVE – Delete invalid objects or faces

This button (qb_tb.validate) opens a dialog with checkboxes for each issue type:

  • Remove Invalid Geometry
  • Remove Invalid UVs
  • Remove Degenerated UVs
  • Remove Out of Range
  • Remove Multiple Materials

Depending on the active scope:

  • Objects: Deletes all mesh objects that have any of the checked issues. Non‑mesh objects (empties, cameras) are also removed if "Invalid Geometry" is checked.
  • Vertex Groups: Deletes only the faces belonging to vertex groups that have the checked issues. The vertex groups themselves remain, but their faces are removed from the mesh.

After removal, a detailed report is shown in the info line.

Choose which issues trigger deletion.

Filter Dropdown

The filter changes depending on the selected scope.

For Objects scope:

  • Quadblocks – valid quadblock objects
  • Triblocks – valid triblock objects
  • Invalid Geometry – objects with NGons, non‑mesh, or invalid block structure
  • Invalid UVs – UVs outside 0‑1 range
  • Invalid Triblock UVs – triblocks with incorrect UV arrangement
  • Degenerated UVs – all UVs identical
  • NGons – faces with >4 vertices
  • Non‑Mesh – empties, cameras, etc.
  • Out of Range – bounding box extends outside -500..500
  • Multiple Materials – more than one material on faces
  • All Invalid – any of the above issues

For Vertex Groups scope:

  • Quadblocks – valid quadblock groups
  • Triblocks – valid triblock groups
  • Invalid Geometry – groups that don’t form a valid block
  • Invalid UVs – UVs outside 0‑1 range in the group
  • Invalid Triblock UVs – triblock groups with wrong UV arrangement
  • Degenerated UVs – all UVs identical in the group
  • Out of Range – any vertex of the group outside -500..500
  • Multiple Materials – faces in the group use more than one material
  • All Invalid – any of the above issues
Choose the issue category to work with.

Important: Out‑of‑Range Detection

The Out of Range check always uses a fixed bounding box from (-500, -500, -500) to (500, 500, 500) — a cube of 1000 units per side, centered at world origin. This is hardcoded and does not depend on the optional Range Box object.

The Range Box is only a visual reference. Even if you delete it, the Validator will still flag objects/groups outside the 1000‑unit cube.

Render Module

The Render module provides real‑time PS1‑style rendering effects using color attributes and compositor overrides. All effects are non‑destructive and can be toggled on/off.

ON/OFF (Toggle CTR Render)

Enables or disables the entire CTR render effect. When ON, the active viewport switches to Material Preview mode and the chosen blend mode is applied. The effect uses the VertexColor color attribute as the foreground and the mesh’s base material as background.

Turn the PS1 effect on and off instantly.

Blend Mode

Select how the VertexColor attribute combines with the base material. Available modes:

Mode Formula Effect
Half Transparent Background/2 + Foreground/2 Soft blend – both layers contribute equally.
Additive Background + Foreground Bright, glowing overlay – foreground adds to background.
Subtractive Background - Foreground Darkens the background – foreground subtracts.
Additive Translucent Background + Foreground/4 Subtle additive – foreground has reduced intensity.
Each blend mode produces a distinct visual result.

Apply (Refresh Shader)

Forces the shader to reload with the current settings. Use this after changing the blend mode or if the effect does not update automatically. Also useful after editing the VertexColor attribute.

Re‑apply the shader without toggling the effect.

PS1 Resolution (Blender 3.5+)

When enabled, the 3D Viewport is rendered at a low resolution (512×216) and upscaled, mimicking the low‑resolution look of PlayStation 1 graphics. This override requires Blender 3.5 or newer.

This effect overrides the viewport’s native resolution. Disable it for regular editing.
Low‑pixelated viewport reminiscent of PS1.

Vertex Snap (Blender 4.0+)

Adds a Geometry Nodes modifier named VX_WorldSnap to the active mesh object. This modifier snaps vertices to a configurable grid, creating a blocky, low‑poly aesthetic. The grid size is adjustable (default 0.1). Requires Blender 4.0 or higher.

Snap vertices to a coarse grid for a chunky look.

Split Screen

Converts the active Properties Editor area into a second 3D Viewport. Useful for comparing the original mesh and the rendered effect side‑by‑side. Press again to revert (if supported).

Duplicate the 3D view to compare with/without effect.

Important Requirements

The CTR Render effect relies on a single Color Attribute named exactly VertexColor. Extra or renamed attributes will break the shader. Ensure your mesh has this attribute with per‑face‑corner colors.

If you don’t see any effect, check that:

  • The mesh has a Color Attribute called VertexColor.
  • The object is in Material Preview or Rendered viewport shading.
  • Blend mode is not set to “None”.
  • You have clicked Apply after changing settings.
Make sure your mesh has the VertexColor attribute.

Exporter Module (QB/TB Export)

The Exporter module exports quadblocks and triblocks to OBJ format, optimised for CrashTeamEditor and other CTR track editors. It includes powerful filtering, preprocessing, texture handling, and duplicate management.

Export Operator (File → Export → Qb/Tb .obj)

The main export operator provides full control over all settings. Access it from the top menu: File → Export → Qb/Tb (.obj). A detailed panel lets you configure scope, types, preprocessing, filters, output folder structure, textures, and metadata.

Full export settings panel.

Quick Export (Ctrl+Shift+E)

Exports using the last used settings (saved in scene.last_export_path). No dialog appears – it immediately exports to the same project folder with the scene name. If no export path exists, a regular export is required first.

One‑key export with previous settings.

Export Scope & Type Selection

Choose whether to export only selected objects (Selection Only) or all objects in the scene. Then select which block types to include: Quadblocks and/or Triblocks.

Preprocessing

Two options prepare meshes before validation:

  • Apply Modifiers – applies all modifiers on each object (non‑destructive, restores original after export).
  • Separate by Loose Parts – splits a mesh into multiple objects based on connected components. Useful when multiple blocks are merged into one object.
Apply modifiers and separate loose parts.

Issue Filtering

Filter out blocks with specific problems. Checked issues cause the block to be excluded from export:

  • Out of Range – vertices outside the fixed 1000‑unit cube (-500..500).
  • Invalid UVs – UV coordinates outside the 0‑1 range.
  • Invalid Triblock UVs – triblocks where UV arrangement does not match the expected pattern (adjacent triangles share UVs).
  • Degenerated UVs – all UVs identical (collapsed).
  • Multiple Materials – a block uses more than one material.

By default, issues are excluded. Tick an option to allow exporting blocks with that issue.

Control which problematic blocks are exported.

Duplicates Export

Powerful feature for batch processing and prototyping:

  • Export Duplicates – creates a full copy of all detected blocks (by group) inside a duplicates/ subfolder. The duplicates are exported as separate OBJ files (one per block) without further processing. Ignores all issue filters.
  • Export Processed – after duplication, the addon runs the main export pipeline on the newly created processed objects (inside the Processed_Blocks collection). This allows you to, for example, export duplicates and then export a final combined OBJ with all filters applied.

When both are enabled, the export flow is: duplicate all blocks → export duplicates → then export the processed collection using your current export settings.

Generate individual copies and a final processed model.

Output & Folder Structure

When Export to Folder is enabled, the exporter creates a clean, organised output:

  • A project folder named after the scene (e.g., MyScene_increment/ or MyScene_replace/).
  • Inside, a numbered subfolder (001/, 002/, …) for each export to avoid overwriting.
  • Inside that, an export/ folder containing the final OBJ and an optional textures/ folder.
  • Log folder (log/) for JSON details files.

Folder Behavior: Replace overwrites the previous export; Incremental creates a new numbered folder each time.

Organised output for versioning.

Texture Handling

Two texture modes are available when Include Textures is checked:

  • Copy Textures – copies all referenced texture images (external or packed) to a textures/ folder next to the OBJ.
  • Remap Textures – same copy, but also updates the material nodes inside Blender to point to the new copied texture paths. This ensures the exported OBJ/MTL uses relative paths. After export, original paths are restored.
Remap Textures temporarily modifies materials. The operation is reversible – original texture paths are restored automatically.
Keep textures together with the model.

Export Details (JSON)

Generates a Details.json file inside the log/ folder. Contains:

  • Export timestamp, Blender version, addon version.
  • Counts of exported quadblocks/triblocks, objects with UV issues.
  • Per‑block issue list (only for blocks that have at least one issue).
  • Full export settings used.

Helps with debugging and tracking export history.

Machine‑readable export report.

Internal Export Flow

Behind the scenes, the export pipeline consists of:

  1. Preprocessing – apply modifiers, separate loose parts.
  2. Validation – filter objects by type and issue settings.
  3. Texture handling – copy/remap textures.
  4. OBJ export – using Blender’s native OBJ exporter (wm.obj_export on 3.3+).
  5. Restoration – revert any temporary changes (modifiers, view layer links, PS1 render state, vertex snap modifiers).

The system is designed to be non‑destructive and restore the scene to its original state after export.

Important Notes

  • The exporter temporarily disables PS1 Render and Vertex Snap modifiers to avoid conflicts.
  • Objects that are not quadblocks or triblocks are ignored.
  • If no objects pass the filters, a detailed error message explains why (e.g., “Found 12 Quadblocks but none passed UV filters”).
  • Quick Export uses the last export path from a regular export. If none exists, you must perform a full export first.

Material Manager

The Material Manager is a dedicated panel in the Properties Editor → Material context. It lists all materials (normal, constant, navigation points) from the active object and provides operations to rename, remap textures, assign to selection, and select/deselect by material families.

Filter & Search

Filter materials by type:

  • All – all materials in the scene (global).
  • Normal – materials of the active object that are NOT constant/nav points.
  • Constant – constant materials of the active object (non‑navigation).
  • Nav Point – navigation point materials of the active object.

Use the search box to filter by name.

Quickly switch between material categories.

Assign (Selected Faces)

Assigns the selected material to the currently selected faces in Edit Mode. If the faces belong to a detected quadblock or triblock, the entire block receives the material. If the material is a constant/navigation material, the operator is disabled – use the “Assign” button inside the Item List (Constant Materials mode) for those.

Assign whole blocks or individual faces.

Select / Deselect (Popup Scope)

Selects (or deselects) faces that use the selected material. A popup offers four scopes:

  • Checked – only the exact material selected.
  • Full – the base material + all its constant materials (including nav points).
  • Constants – only constant materials derived from the base (excludes base and nav points).
  • Nav Points – only navigation point constants.

This is extremely useful for selecting all variations of a texture family (e.g., all “Grass_ID*” materials) in one click.

Select the whole material family or just constants.

Rename (Base + ID)

Smart renaming that understands constant materials:

  • For a normal material – simple rename, checks for conflicts with base names used by constants.
  • For a constant material – separate fields for base name and ID. Renaming the base renames the entire family (all constants with that base). Renaming the ID only affects the selected constant. Uniqueness of IDs is enforced.
  • For a base material that has constants – renaming the base automatically renames all its constant materials accordingly.

All rename operations validate that the new name does not conflict with existing materials or base‑name usage.

Rename base and propagate to all constants.

Remap (Texture)

Changes the texture image for a material and all derived materials (base + constants that share the same original material). You can select a new image from the dropdown or load from file. The remap function ensures the image is assigned to the first TEX_IMAGE node (or creates one if missing).

If PS1 Render is active and a material lacks a texture node, the effect is temporarily disabled to allow node creation, then restored. This guarantees that constants without nodes can still be remapped.

Batch‑update textures across an entire material family.

Refresh & Purge Unused

Rebuilds the material list after adding, renaming, or deleting materials. Optionally purges all unused data blocks (materials, textures, images) from the blend file, helping to keep the project clean.

Keep your material list up‑to‑date.

List Interface

The material list displays each item with its texture preview icon (if available). Click the checkbox to select a material. The selected material is highlighted and used by the Assign/Select/Deselect/Rename/Remap buttons. Pagination (10 items per page) and scroll buttons help navigate long lists.

Visual material selection with texture previews.

Important Notes

  • The Material Manager only affects the active mesh object.
  • Assigning a material through this panel will not create constant materials – use the Item List’s “Assign” button for that.
  • Remapping textures uses the first TEX_IMAGE node found. For materials with multiple texture nodes, only the first is updated (this is by design).
  • Renaming a base material that has constants will also rename the constants, but the operation checks for ID collisions with other families.

Range Box Module

The Range Box is a visual reference that shows the 1000‑unit cube used by the Validator for “Out of Range” detection. It does not affect validation logic; the Validator always uses the hardcoded box from (-500,-500,-500) to (500,500,500).

Add Range Box

Creates a new empty object named “Range” with a wireframe display that outlines the 1000‑unit cube. The wireframe is visible in the 3D viewport, making it easy to see which objects or blocks lie outside the valid range.

You can add it via the menu: Add → CTR → Range Box.

Add the visual helper from the Add menu.

Visual Properties

The Range Box is an empty with a custom wireframe cube. You can move, scale, or delete it – it will not affect any validation. However, you cannot change its size; it always represents the same 1000‑unit cube. If you need a different range, you must modify the Validator’s internal values (not exposed in UI).

The addon does not provide any interface to change the box’s colour or line thickness. Its appearance is the default Blender empty wireframe.

The box is purely visual – moving or scaling it does nothing to validation.

Important: Validation is Independent

The Validator’s “Out of Range” check ignores the Range Box object entirely. Even if you delete the Range Box, or move it elsewhere, the out‑of‑range detection still uses the fixed coordinates (-500,-500,-500) to (500,500,500). The Range Box is only a convenience to help you position your geometry inside the safe zone.

Do not rely on the Range Box to change validation behaviour. It is a visual aid only.
Out‑of‑range detection always uses the fixed cube.

Addon Updater

The addon updater automatically checks for new versions of the CTR Toolkit on GitHub and provides a simple one‑click installation. It is based on the reliable CGCookie updater and includes backup/restore capabilities.

Automatic Update Checking

When enabled in preferences, the updater periodically checks GitHub for new releases. The check interval is fully customisable (months, days, hours, minutes). If an update is found, the Blender icon in the CTR panel header turns red. Click it to open the installation popup.

Red Blender icon signals an update is ready.

Manual Check

You can manually check for updates at any time via the Update Settings panel inside Blender Preferences: Edit → Preferences → Add-ons → CTR Toolkit. The panel also shows the status (up to date, error, checking) and the timestamp of the last check.

Check now and view status from addon preferences.

Install Update Popup

When an update is available, clicking the red Blender icon opens a dialog with three choices:

  • Update Now – downloads the new version and installs it (a backup is created automatically).
  • Ignore – dismisses the update for this version (prevents future popups for the same version).
  • Defer – closes the popup and reminds you again in the next Blender session.

The installer can perform a clean install (deletes the old addon folder before copying the new one) or a standard merge (overwrites only changed files).

One‑click update from the popup dialog.

Update Settings (Preferences)

Located in the addon preferences, the update settings panel gives you full control:

  • Auto‑check toggle – enable/disable automatic checks.
  • Interval configuration – set months, days, hours, minutes between checks.
  • Status display – shows if an update is available, or if there was an error.
  • Primary buttons – “Check for Updates”, “Install <version>”, “Ignore”, etc.
  • Advanced options – “Install Specific Version” (rollback to a previous release) and “Restore Backup” (if a backup exists).
Full control over update behaviour.

Backup & Restore

Before installing an update, the updater creates a backup of the current addon folder (excluding patterns like __pycache__). If something goes wrong, you can restore the previous version using the Restore Backup button in the advanced section. The backup is stored inside the blender_ctr_toolkit_updater/ folder.

Safe updates with automatic backup.

Install Specific Version

Sometimes you may need to revert to an older release. The updater can download and install any previous tag (release) from the GitHub repository. A dropdown lets you select the desired version. This is perfect for troubleshooting or working with legacy projects.

Roll back to any previous version.

Testing Mode (fake_install)

For development and testing, the updater includes a fake_install flag. When enabled, it simulates an update without actually downloading or modifying files. This allows you to test the UI and callback logic without affecting the real addon.

Safe testing of the update flow.

Important Notes

  • After an update, Blender must be restarted to fully reload the addon (the updater shows a restart prompt).
  • The updater only works with GitHub releases (not branches). The repository owner and repo name are hardcoded to kjorgecaballero/blender-ctr-toolkit.
  • If you have modified the addon files manually, a clean install will remove those changes. Back up your modifications before updating.
  • The updater requires an internet connection to check for updates and download the ZIP.
  • On some systems, SSL certificate errors may occur. The updater will fall back to a manual download link in such cases.
