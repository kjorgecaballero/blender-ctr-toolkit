# Issue Tracking

We use GitHub Issues to track bugs, feature requests, and tasks.

## Issue Templates

- **Bug Report** – Use when something does not work as expected.
- **Feature Request** – Use when you have an idea for a new capability.

## Before Opening an Issue

- Search existing issues (including closed ones) to avoid duplicates.
- Make sure you are running the latest version of the addon.
- Restart Blender to confirm the issue is not a temporary glitch.

## What to Include in a Bug Report

- Blender version (e.g., 4.2.0).
- CTR Toolkit version.
- Steps to reproduce the bug.
- What you expected to happen vs. what actually happened.
- Any error messages from the System Console (Window → Toggle System Console on Windows).

## What to Include in a Feature Request

- A clear description of the problem you are trying to solve.
- How you imagine the feature working (UI, operator, keymap, etc.).
- Why it would be useful for other users.

## Labels

Maintainers will apply labels such as `bug`, `enhancement`, `help wanted`, etc. to help organise work.

## Issue Lifecycle

- **Open** – The issue has been reported.
- **Triaged** – A maintainer has acknowledged it.
- **In Progress** – Someone is working on it.
- **Closed** – Fixed or declined with a comment.
